# Phase 5 plan — explainer infrastructure (auto-approved, autopilot)

## 5.1 Manifest + loader
- `src/components/explainers/manifest.json`: `{ "<concept-id>": { "module": "laws2400/CalculusSimulation", "base": "simulation" } }`.
  Append-only (the build-explainer skill never rewrites other entries); validate.mjs checks every key is a real concept
  and every module file exists; gate counts entries.
- `ExplainerHost` (React island, client:visible) on the concept page, above the concept text (research rule: interact
  first). It lazy-loads the module via `import.meta.glob('./**/*.tsx')`, so every explainer is its own chunk.
- Layout context: `pinned` when viewport ≥ 1100px and motion = full; otherwise `paced` (Next/Back buttons). Motion off
  → bases show the final frame with stacked captions.
- Every explainer ends with one check question (`ExplainerCheck`) recorded as an attempt
  (`questionId: explainer:<concept>`), so it feeds the criterion tracker.

## 5.2 Bases
- ScrollExplainer: GSAP timeline scrubbed over N screens when pinned; beats advanced by Next when paced; 20-second terms
  beat first; captions fade per beat; off = final frame + stacked captions.
- Simulation: controls bound to a pure `state → view` function, Reset, a "what changed" caption computed from the diff.
- Palace: Three.js room walk (ThreeScene); each locus one element; arrow keys / scroll / Next to advance.
- ThreeScene: plain `three` (tree-shaken, no r3f), mounts when in view, pauses off-screen (IntersectionObserver),
  DPR ≤ 1.5, one post pass (3% grain, 8% vignette) and a soft glow on the amber light only; PNG/SVG fallback when
  motion is off or WebGL fails.
- Budget script `scripts/budget.mjs`: after build, gzip-size each explainer chunk (its own code + non-shared imports);
  fail > 120 KB gz. The shared `three` vendor chunk is reported separately (budget 180 KB gz) because it is loaded
  once for every 3D explainer.
