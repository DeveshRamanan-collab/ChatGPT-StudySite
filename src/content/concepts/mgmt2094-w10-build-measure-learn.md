The lean start-up's core element is a loop: **Build** (experiments) → **Measure** (metrics, against a
baseline) → **Learn** (analyse, then pivot or persevere) → a new hypothesis → Build. A fuller version runs ideas →
build → code → measure → data → learn → ideas, with one instruction: **minimise the total time through the loop** —
build faster (continuous deployment, small batches, MVP, refactoring), measure faster (split testing, actionable
metrics, net promoter score), learn faster (customer development, five whys).

**Validated learning** plans the loop in reverse: 1) What do we need to learn? 2) How can we measure it? 3) What is the
simplest thing to build to measure it (the MVP)?

The **innovation accounting report** records each experiment: background (why is it relevant?); a falsifiable
hypothesis (quantify your goals, set scope/timebox, test the value and growth hypothesis first); build (plan how to
execute the experiment); measure (results = data); learn (document the learning as validated, invalidated or
inconclusive); and the next action (move to the next experiment).

At Learn the venture decides to **pivot or persevere**. A one-page lean start-up sheet based on Ries lists pivot types
across the business, including technology, platform, zoom-in, zoom-out, channel, engine-of-growth, customer segment,
customer need, value capture and business architecture pivots.

Exam use: write the hypothesis so a result could disprove it, then say which result would trigger a pivot.
